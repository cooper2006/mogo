# 数据变更兼容性矩阵（024 T050 / FR-024）

灰度发布常伴随数据层变更（schema、数据修正、枚举）。本矩阵列出常见数据变更类型的
**可回滚性**、回滚方式与风险等级，供 canary 档位推进前评审（对应 canary-plan.yml 的
`checkpoints` 与 rollback-conditions.yml 的 `scope`）。

适用范围：MongoDB（mongo-data / mongo-backup 卷）、Redis（redis-data 卷）、
Weaviate（weaviate-data 卷）以及业务服务内嵌 schema 变更。

| 变更类型 | 是否可回滚 | 回滚方式 | 风险等级 | 兼容性要求（canary 与 stable 共存） |
| --- | --- | --- | --- | --- |
| 新增可选字段 / 列 | ✅ 可回滚 | 反向脚本删除字段；不删数据 | 低 | 新旧版本均兼容（旧版忽略未知字段） |
| 新增必填字段（带默认值） | ✅ 可回滚 | 反向脚本改回可选 | 低-中 | 旧版读写新字段需默认值兜底 |
| 新增必填字段（无默认值） | ⚠️ 高风险 | 先补默认值再回滚 | 中-高 | 灰度期间必须双写（旧版写 null 会失败） |
| 删除字段 / 列 | ⚠️ 需备份 | 从备份恢复或重建字段 | 中-高 | 旧版读取已删字段会报错 → 先弃用再删 |
| 重命名字段 | ⚠️ 需双写窗口 | 反向重命名 + 双写回滚 | 中-高 | 灰度期新旧字段并存，稳定版写旧字段 |
| 修改字段类型 | ❌ 高风险 | 备份恢复（mongodump / mongorestore） | 高 | 类型收紧（str→int）在旧版会失败 |
| 新增唯一索引 | ✅ 可回滚（需确认唯一性成立） | drop 索引 | 中 | 唯一约束对稳定版写入也生效 |
| 新增普通索引 | ✅ 可回滚 | drop 索引 | 低 | 无兼容性影响，仅回滚耗时 |
| 数据批量修正（一次性脚本） | ⚠️ 幂等 + 备份 | 反向脚本或备份恢复 | 中-高 | 修正期间稳定版写入旧值会再次污染 |
| 枚举值新增 | ✅ 可回滚 | 反向脚本移除值 | 低-中 | 旧版读新枚举值需容错 |
| 枚举值改名 | ⚠️ 需双写窗口 | 反向改名 + 回迁数据 | 中-高 | 灰度期两值并存 |
| 服务内部 schema（Mongoose/Pydantic 模型）变更 | 随代码回滚 | git 回滚代码 + 重启 | 低（数据不变） | 数据层无需迁移即可回滚 |
| Redis key 结构变更 | ✅ 可回滚（数据在内存/持久化 AOF） | 反向脚本重写 key | 低-中 | 旧版读新结构需容错 |
| Weaviate collection schema 变更 | ⚠️ 需重建 collection | 备份恢复 + 重建 | 中-高 | 向量维度/字段变更需新旧共存（多 collection） |

## 关键原则

1. **向后兼容优先**：任何数据变更都应保证 `canary` 版本回滚后，`stable` 版本能继续正确读写。
2. **双写窗口**：字段改名、枚举改名、类型调整必须有一段"新旧并存 + 双写"的过渡期，
   结束条件是稳定版不再读旧字段。
3. **备份前置**：中高风险变更在 canary 推进前必须完成一次全量备份
   （`./mogo backup`，写路径 mongo-backup 卷 / `/backups`），并记录备份时间。
4. **回滚验证**：回滚后跑 `scripts/release/verify_rollback_baseline.py` 校验业务指标回到基线；
   数据层面用 `mongosh`/`redis-cli` 抽样确认字段可用。
5. **不可逆变更**（改类型、删字段）必须走"先弃用 → 观察 ≥ 1 个完整灰度周期 → 再删除"的流程。

## 与灰度档位的联动

- 1% 档：只允许"低风险"变更；观察点：新增字段被 canary 正常读写。
- 10% 档：允许"低-中"变更；观察点：双写窗口正常、唯一索引无冲突。
- 50% 档：允许"中"变更；观察点：稳定版仍能读写、备份已生成。
- 100% 档：允许全部变更；之后进入弃用期再清理旧字段/旧值。
