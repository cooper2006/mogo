# 扩展-收缩流程（024 T057 / FR-030）

破坏性变更 MUST 使用 **expand / contract** 多版本流程：三阶段互相兼容，**未完成收缩禁止回滚**。
本流程覆盖 MongoDB / Redis / Weaviate 数据变更，与 `deploy/runbook/data-rollback-matrix.md` 配合。

## 三阶段

### 阶段 1 — 扩展（Expand）

- 目标：在**不破坏旧版本**的前提下引入新结构。
- 动作：新增字段/表/索引/新值；保留旧字段与旧值读取路径；必要时双写（同一事务同时写新旧字段）。
- 兼容性：**新版本可写，旧版本可读**（旧版本忽略新字段）。
- 灰度档位：允许在 1% 档推进（低风险项）。

### 阶段 2 — 迁移（Migrate）

- 目标：把存量数据从旧结构迁移到新结构，`scripts/migrations/` 下提供幂等迁移脚本。
- 动作：分批、可重试、不阻塞线上（见 `scripts/migrations/README.md` 的规范）；
  迁移期间新旧字段并存，旧字段仍被稳定版读取。
- 完成条件：存量数据 100% 迁移成功，且连续一个完整灰度周期（≥ 50% 档窗口）无异常。
- 灰度档位：10% → 50% 档推进。

### 阶段 3 — 收缩（Contract）

- 目标：删除旧字段/旧值/旧索引，清理死代码。
- 动作：先停止写旧字段（观察窗口），再停止读旧字段，最后删除旧结构。
- 兼容性：收缩后只有新版本能运行（新版本已全量发布 ≥ 100% 档）。
- 灰度档位：100% 档之后、下一版本发布时执行。

## 硬性规则

1. **未完成收缩禁止回滚**：若在收缩阶段需要回滚，必须先回到迁移完成态（阶段 2 结束态），
   否则稳定版会因读不到已删除字段而失败。`deploy/cli/canary.sh rollback` 的 `--reason`
   若标记为 `contract-phase` 会先触发迁移回退（`scripts/migrations/<n>.down.py`）。
2. **三个版本 MUST 互相兼容**：vN（旧）、vN+1（过渡）、vN+2（新）在发布窗口内必须能同时读写。
3. **双写窗口**：字段改名、枚举改名、类型调整必须双写 ≥ 一个完整灰度周期。
4. **迁移前置备份**：每次迁移前 `./mogo backup`，备份时间写入发布记录。
5. **迁移说明**：每次破坏性变更 MUST 附迁移说明（见 `docs/migration-notes/TEMPLATE.md`），
   纳入发布检查单（`docs/release-checklist-self-hosted.md`）。

## 与灰度档位联动

| 阶段 | 灰度档位 | 允许变更等级 | 观察点 |
| --- | --- | --- | --- |
| Expand | 1% → 10% | 低风险 | 新旧字段并存、稳定版读写正常 |
| Migrate | 10% → 50% → 100% | 中风险 | 迁移幂等、无阻塞、存量 100% 完成 |
| Contract | 100% 后下一版本 | 高风险 | 旧字段已停止读写后再删除 |

## 回滚决策树

```
是否处于 Contract 阶段？
├─ 否（Expand / Migrate）→ 直接 canary.sh rollback（数据兼容，稳定版可读）
└─ 是 → 先执行 <n>.down.py 回到 Migrate 完成态 → 再 canary.sh rollback
```
