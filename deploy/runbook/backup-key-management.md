# 备份密钥管理 Runbook（024 T066 / FR-035）

> 约束：**备份加密密钥 MUST NOT 与备份集同机存放**。若密钥与备份同盘/同机，
> 攻击者同时拿到两者等于没有加密；这也让 DR 恢复依赖同一个故障域。
> 本文件把密钥来源、生成、轮换、异地存放与 DR 演练必测项写成可执行清单。

---

## 1. 密钥来源（只允许这四种，禁止内置默认口令）

| 来源 | 配置方式 | 适用场景 |
|---|---|---|
| 环境变量 | `MOGO_BACKUP_KEY` | 由 systemd unit / cron 环境注入（临时，不落仓库） |
| 密钥文件 | `MOGO_BACKUP_KEY_FILE=/path/to/key` | 推荐：密钥文件挂在**另一台主机**的只读路径 |
| secrets 卷 | 把密钥文件放入 `deployment-secrets` 卷，`MOGO_BACKUP_KEY_FILE` 指向卷内路径 | 与 mogo 栈同机（**不满足异地要求**，仅限本地开发） |
| 外部密钥管理 | 从 Vault / KMS 取到 env 后注入 | 生产首选 |

**红线**：
- 禁止把密钥写进 `flags.yml` / `.env` 提交到仓库（`scripts/check-secrets.sh` 会拦截）。
- 禁止空口令 / `"changeme"` / 版本号等弱口令；最小强度建议 ≥ 32 字节随机值。
- 密钥文件权限 `chmod 600`，属主为运行备份的用户。

---

## 2. 异地存放要求（核心）

1. **异机**：密钥存放在与备份集不同的主机（或不同故障域的挂载点）。
2. **不同副本**：至少保存 2 份密钥副本，分属不同位置（例如公司保险柜 + 另一台离线机）。
3. **不随备份集传递**：备份目录内**只**写 `KEY_SHA256_PREFIX`（密钥 sha256 前 32 位十六进制，
   用于校验密钥是否匹配），**绝不**写密钥本体或可逆派生。
4. **离线副本**：至少 1 份密钥副本在离线介质上，标注备份集的时间范围，便于跨期恢复。

---

## 3. 生成新密钥

```bash
# 生成 32 字节随机密钥（base64），输出到标准输出
openssl rand -base64 32
```

生成后：
1. 立即写入目标位置（如 `sudo install -m 600 /dev/stdin /etc/mogo/backup-key`）。
2. 记录 `KEY_SHA256_PREFIX`（与备份目录内一致）到离线记录，便于识别用哪把密钥。

---

## 4. 轮换

| 触发 | 动作 |
|---|---|
| 常规 | 每 90 天或每 20 次备份轮换一次 |
| 人员离职 | 立即轮换该人员接触过的密钥 |
| 疑似泄露 | 立即轮换 + 重新加密受影响备份集 + 记录事故 |

轮换步骤：
1. 生成新密钥并配置到备份任务（`MOGO_BACKUP_KEY` / `MOGO_BACKUP_KEY_FILE`）。
2. 跑一次加密备份，验证新密钥可加密、可解密（`mogo_backup` + `mogo restore --verify`）。
3. 旧密钥**保留**至所有用旧密钥加密的备份集过期（保留策略 T069 生效后）再销毁。
4. 更新离线记录中的 `KEY_SHA256_PREFIX` 列表。

## 5. DR 演练必测项（每次 DR 演练都要打勾）

| # | 必测项 | 判定 | 结论 |
|---|---|---|---|
| K1 | 从**异地**取回密钥文件（不是备份集所在机器） | 路径可读、权限 600 | |
| K2 | 用该密钥解密最近一次备份集 | `openssl enc -d ... -pass stdin` 成功，`SHA256SUMS -c` 通过 | |
| K3 | 密钥指纹与备份目录 `KEY_SHA256_PREFIX` 一致 | 一致 | |
| K4 | 错误密钥被拒绝（避免误用旧密钥静默解出垃圾） | 解密失败并报指纹不匹配 | |
| K5 | 完成后密钥放回异地保管处 | 已归位 | |
| K6 | 演练耗时记录 | 记入 `deploy/runbook/rollbacks/` | |

## 6. 与备份流程的联动

| 机制 | 位置 |
|---|---|
| 加密/解密实现 | `deploy/cli/backup.sh` 的 `mogo_backup_encrypt_dir` / `mogo_backup_decrypt_dir` |
| 单测 | `scripts/test_backup_encrypt.sh`（含错误密钥拒绝、无密钥失败） |
| 保留策略 | `deploy/cli/backup-schedule.sh`（过期清理时先确认密钥已可解，再删） |
| 告警 | 解密失败 / 密钥不可读 → 通过 Alertmanager 发 P1（复用既有渠道，见 `deploy/alertmanager/alertmanager.yml`） |

## 7. 常见坑

- **把密钥和备份放同一块盘**：备份集被泄露 = 密钥一起泄露。用 `df` 核对两者挂载点不同。
- **备份目录写密钥副本"方便恢复"**：违反 K3/K4 红线，且 `scripts/check-secrets.sh` 会拦截。
- **轮换后立即删旧密钥**：旧备份集无法解密。必须等所有用旧密钥的归档过期。
- **只用一把密钥跑全量**：单点风险。至少保留当前 + 上一把，共两把可用密钥。
