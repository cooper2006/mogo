# 灾备预案（DR Plan）（024 T082/T088/T089 / FR-042/FR-043/FR-045）

本预案定义自托管 mogo 部署的灾备场景、决策链、切换与恢复步骤、通信方式与 RTO/RPO 目标。
**每次演练实测值达标后**按 T089 更新 §7 的正式承诺值。版本号见文件末尾。

## 1. 场景清单

| 编号 | 场景 | 数据影响 | 触发判定 | 对应 runbook |
| --- | --- | --- | --- | --- |
| S1 | 单容器崩溃（应用） | 无数据丢失 | 健康检查连续 3 次失败 + 容器重启失败 | `deploy/runbook/rollback-runbook.md` |
| S2 | 数据库不可用（MongoDB 宕机） | 无数据丢失（副本集/备份完好） | `docker compose ps mongo` 非 running | `failover-runbook.md` |
| S3 | 数据丢失 / 损坏（误删、坏盘） | **数据丢失** | 应用报缺数据 + 备份校验失败 | `failover-runbook.md` §2.3 restore |
| S4 | 主机不可用（整机宕机） | 可能丢最近备份后写入 | 主机 ping 不通 + 监控告警 | `failover-runbook.md` |
| S5 | 可用区 / 区域不可用 | 同 S4 | 云控制台告警 + 多主机同时不可达 | `failover-runbook.md` |
| S6 | 配置 / 版本回滚需求 | 无数据丢失 | 发布后 P0 指标劣化 | `rollback-runbook.md` + `deploy/canary/rollback-conditions.yml` |

## 2. 决策链

| 角色 | 可决策范围 | 审批要求 |
| --- | --- | --- |
| SRE 值班（oncall） | S1/S6 直接处置 | 无（按 runbook 执行） |
| SRE 负责人 | S2/S3/S4/S5 发起切换 | P0 事故单 |
| 平台负责人 | 跨区切换 / 回切 | P0 事故单 + 双人复核（`MOGO_FAILOVER_REQUIRE_APPROVAL`） |
| 研发负责人 | 业务影响评估 | 无 |

**决策时限**：P0 事件（全部业务不可用）决策 ≤ 10 分钟；P1（部分功能）≤ 30 分钟。

## 3. 切换与恢复步骤（摘要，详见各 runbook）

1. **确认**：按 §1 判定场景编号，P0 立即建事故单。
2. **止血**：S6 走 `deploy/cli/auto-rollback.sh` / `canary.sh rollback`；S3/S4/S5 走 `./mogo failover execute --new-host <IP>`。
3. **恢复**：备份恢复 → `./mogo restore <dir> --yes [--verify]`（T072 自动业务校验）。
4. **验证**：`./mogo failover verify`（一致性 FR-041 + 业务 FR-037）。
5. **复盘**：写入 `deploy/runbook/drills/<YYYY-MM-DD>-<scenario>.md`，问题必须三栏闭环（T087）。

## 7. RTO / RPO 目标（FR-043，演练实测达标后固化）

| 场景 | RTO 目标 | RPO 目标 | 来源 |
| --- | --- | --- | --- |
| **无副本集**（默认单机 mongo） | 备份恢复时长（= `./mogo restore` 实测） | 最近一次成功备份时刻 | 演练实测后写入 |
| **有副本集**（`mongo-ha`，T074） | 副本集故障转移时间 | 0（副本集自动同步） | 演练实测后写入 |
| S1 应用崩溃 | ≤ 5 分钟（自动拉起） | 0 | 设计承诺 |
| S6 配置回滚 | ≤ 10 分钟 | 0 | 设计承诺 |

> **注意**：§7 目标值 MUST 以真实演练实测为准（T089），未演练前不对外承诺；
> 无副本集场景 RPO 不做承诺（同 T075 声明）。

## 8. DR 演练计划（T088 / FR-045）

- **频率**：至少 **每季度一次**（Q1/Q2/Q3/Q4 末月），轮流覆盖场景 S3（数据丢失）、S4/S5（主机/区域不可用）。
- **记录**：每次演练在 `deploy/runbook/drills/<YYYY-MM-DD>-<scenario>.md` 记录日期、场景、RTO 实测、RPO 实测、发现问题、整改闭环状态。
- **未闭环处理**：问题未三栏（责任人+修复+验证）闭合前，不得关闭演练记录（T087），下次演练先复验。
- **变更触发**：架构变更（新增副本集、改备份策略、改镜像 digest）后 30 天内补一次演练。
