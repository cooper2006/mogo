## 二、修复详情

### 2.1 QF-420（P0 阻断级）：skills_specs 解包脚本 zip-slip 路径穿越

**问题**：`skills_specs/{docx,pptx,xlsx}/scripts/**/unpack.py` 等 14 个脚本直接调用 `zipfile.ZipFile.extractall()`，未校验压缩条目路径。恶意 zip 可用 `../../` 条目写出到目标目录之外，造成任意文件写入。

**修复**：14 个文件统一加入路径穿越防护——逐条目解析并规范化目标路径，拒绝解析后仍越出目标根的条目（未使用 `extractall` 的成员过滤参数，而是显式校验后写入，兼容旧 Python）。

**语义**：这是审计中**唯一的真实安全缺陷**，已修复并有单测覆盖。

### 2.2 tenant_id 迁移测试同步（`da728ba` + `7fb125b`，77 处）

**根因**：业务代码已把租户标识从 `main_id` 体系完整重命名为 `tenant_id` 体系，但测试套件的断言、字段名、方法名、mock 未同步。

| 类别 | 典型漏改 | 数量 |
|---|---|---|
| 字典键 / 键访问 | `{"main_id": ...}` → `{"tenant_id": ...}`、`["main_id"]` → `["tenant_id"]` | 大批 |
| 响应字段 | `c["mainId"]` → `c["tenantId"]` | 2 |
| 常量 | `PLATFORM_MAIN_ID` → `PLATFORM_TENANT_ID` | 3+ |
| 方法 / 属性名 | `add_main_scope` → `add_tenant_scope`、`resolve_main_id` → `resolve_tenant_id`、`_selectable_tenant_main_ids` → `_selectable_tenant_ids`、`directory._main_id` → `directory._tenant_id` | 多处 |
| 调用参数名 | `main_id=` → `tenant_id=`（业务签名已改） | 多处 |
| 测试内部变量 / fake 签名 | `_Policy.filter_candidates(..., main_id, ...)`、`_seed(..., main_id=...)`、`_user`/`_fake` 参数 | 多处 |

**保留项**：`MAIN_ID` 大写常量（示例租户 ID 值，赋给 `tenant_id` 字段语义正确）与 `test_*main_id*` 函数名。

**关键结论**：**业务实现已正确完成迁移，失败纯属测试套件未同步**，无业务缺陷。
