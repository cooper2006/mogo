# 残余风险豁免登记

> 022 FR-27 (T052)。这是一份**活的登记表**，不是模板文件 —— 每次新增豁免
> 都在下表追加一行，并附上完整的四要素记录。

## 原则

接受风险不等于放弃风险。每一条豁免都必须同时具备四样东西，缺一即无效：

1. **风险接受人** —— 有权限承担后果的维护者（不是自动批准）
2. **临时缓解措施** —— 在修复之前实际降低影响的手段
3. **重审日期** —— 最长 90 日；过期自动失效并回到「未修复」状态
4. **补偿性控制** —— 监控 / 告警 / 日志，用于发现被接受的攻击

**不允许**的豁免理由：「太麻烦」「没有工时」「下个版本再说」。
**允许**的豁免理由：上游无补丁且我们可控影响面、业务上无法承受
变更风险且已隔离、误报且已验证不可利用。

## 豁免记录模板

新增豁免时，复制以下模板并在上文表格中登记 ID。

```markdown
### RR-00X：（组件 / 问题一句话）

**登记日期**：YYYY-MM-DD
**到期重审**：YYYY-MM-DD（距登记 ≤ 90 日）

**问题描述**
（漏洞或弱点是什么，来自哪个扫描器 / 报告）

**级别与理由**
CRITICAL / HIGH / MEDIUM / LOW
（CVSS 基础分 + 是否生产可达 + 是否需要认证）

**为什么不能按时限修复**
（上游无补丁 / 兼容性 / 业务约束 —— 必须是实质理由）

**风险接受人**
（有权限承担后果的维护者；不是自动批准）

**临时缓解措施**
（WAF 规则 / 网络隔离 / 功能开关 / 降级配置 —— 必须实际生效）

**补偿性控制**
（监控 / 告警 / 日志 —— 攻击发生时能被发现）

**验证证据**
（如何证明缓解措施生效：命令输出、配置片段、测试用例）

**重审记录**
| 日期 | 结论 | 处理人 |
|------|------|--------|
| YYYY-MM-DD | 首次登记 | |
```

## 失效规则

- 到期未续 → 状态自动置为 `expired`，CI 重新阻断相关检查
- 缓解措施被移除 → 豁免立即失效，不需要等到重审
- 上游发布补丁 → 必须在 14 日内评估是否可以直接修复并关闭豁免
- 同一组件累计豁免 ≥ 3 条 → 触发架构层复盘，不允许继续追加
