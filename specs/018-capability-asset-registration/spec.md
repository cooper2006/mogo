# Feature Specification: Capability Assetization (Discovery → Registration)

**Feature Branch**: `018-capability-asset-registration`

**Created**: 2026-07-08

**Status**: Draft

**Input**: 补齐规划文档清单 14（P2 规模化生态）"能力资产化'发现→注册'"（知识库《PilotMind》生产链路首环）：把存量业务能力（审批/查询/下单等）变成可审计、可版本化的能力资产，注册为可被 Agent 发现和调用的标准化单元。

## User Scenarios & Testing *(mandatory)*

用户故事按优先级排列，每个独立可交付、可测试。

### User Story 1 (P1) — 能力发现（扫描存量业务能力）

系统可扫描/接入存量业务能力（审批/查询/下单等），识别其接口契约，生成待注册资产清单。

**Acceptance Scenarios:**
- 扫描一个业务系统 → 识别可封装的能力（接口/参数/返回）
- 生成待注册资产清单（含契约摘要）
- 未识别的能力 → 标记人工补全

### User Story 2 (P1) — 能力注册为可审计资产

将发现的能力注册为标准化能力资产：契约（输入/输出/错误）、版本、责任人、审计记录；注册后可被 Agent 发现与调用。

**Acceptance Scenarios:**
- 注册能力 → 生成资产（契约 + 版本 + owner + 审计）
- Agent 可发现已注册能力
- 资产调用 → 记录审计（与 001 联动）
- 契约变更 → 版本递增，旧版可回看

### User Story 3 (P2) — 资产版本化与治理

能力资产支持版本管理、状态（active/deprecated）、下线审批；治理侧可查全部资产。

**Acceptance Scenarios:**
- 资产版本递增 → 可回看历史契约
- 下线 → 需审批，留审计
- 治理视图 → 全量资产 + 状态

### Notes / Assumptions
- 本特性补齐规划文档清单 14（P2 规模化生态，后置），属缺口新特性
- 现状：MOGO 有 MCP/工具接入（特性 004 工具/Skill），但无"能力资产"的标准化注册与版本化模型
- 与特性 004（skillhub-lifecycle）的关系：能力资产是 Skill/工具的"资产化"升级（契约 + 版本 + 审计），004 是生命周期基础
- 与特性 012（A2A 网关）的关系：注册的能力资产可经 A2A 对外暴露
- 与特性 001（gatekeeper）的关系：资产调用过 001 门禁/审计
- 能力资产的契约 schema（输入/输出/错误/SLA）需 clarify
- "发现"是自动扫描 + 人工补全，非纯自动

## Functional Requirements

- FR-1: 扫描/接入存量业务能力，识别接口契约；**扫描目标 = 标准 REST 接口 + MCP 工具（自动识别契约）；非标准能力人工登记**
- FR-2: 生成待注册资产清单（契约摘要 + 人工补全标记）；**分工 = 标准 REST/MCP 自动抽取契约，非标准必须人工补全（清单标注"自动/待补"）**
- FR-3: 能力注册为标准化资产（契约 + 版本 + owner + 审计）；**契约 schema = 输入/输出/错误/SLA 四段（JSON 声明式）；owner = 责任到岗位角色（与 006 RBAC 角色映射）**
- FR-4: 注册资产可被 Agent 发现与调用；**资产与 004 Skill 多对多（`skill_refs` 关联，一个资产可被多 Skill 引用）**
- FR-5: 契约变更版本递增，旧版可回看；**"回看" = 旧版契约可查（历史留档），但不可恢复调用（仅最新版可调用）**
- FR-6: 资产状态管理（active/deprecated/下线需审批）；**状态 = active / deprecated / offline（3 态）；下线审批角色 = 006 全能力管理员，留 001 审计**
- FR-7: 治理侧全量资产视图；**视图 = 列表统计 + 下钻到单资产详情（契约/版本/owner/状态/调用量）**
- FR-8: 资产调用过 001 门禁/审计
- FR-9: 能力资产契约 schema 可配置
- FR-10: **能力扫描去重：以"接口端点 + 方法"为去重键，重复发现的同能力识别为同一资产（不重复注册）**
- FR-11: **资产 owner 可转移（责任人调岗），转移留审计**
- FR-12: **资产 a2a_exposed 显式标记：标记为 true 的资产才生成 012 的 AgentCard**

## Non-Goals
- 不实现能力的自动执行（仅注册与治理，执行走既有工具/MCP）
- 不改变 004 既有 Skill/工具契约（资产化是叠加层）
- 不实现能力编排（编排属 010 DAG）
- 不实现跨组织资产市场（资产在组织内）

## Success Criteria
- 存量能力 100% 可发现 + 注册
- 资产调用 100% 进 001 审计
- 契约变更 100% 版本化
- 治理视图 100% 可查全量资产
