## 完整性（Completeness）

- [ ] CHK001 **四概念边界**（员工/岗位角色/Agent/Skill）是否已拍板（OQ-1 为 ADR 级门禁；spec 决策 #1 只声明"不改造 position_roles"，但"Agent"在 mogo 语境的多义性（A2A AgentCard / 子智能体 / 员工）未消解，046 同名概念教训直接适用）
- [ ] CHK002 **EmployeeProfile 快照的字段清单**是否定义（FR-003 说档案注入，Key Entities 说"物化"，但快照含哪些字段、版本号如何标记、会话文档内嵌的尺寸上限未给）
- [ ] CHK003 **能力白名单的粒度与表达**是否定义（决策 #1 沿用 PositionRolePayload 范式：capabilities 开关 + toolIds/skillIds；但员工是否需要 all/selected 双模式、MCP 工具与 HTTP 工具是否同列表、连接器（041）是否纳入未写）
- [ ] CHK004 **知识库挂载的权限继承**是否定义（员工挂载知识库 K，认领用户是否必须对 K 有源权限？030 数据权限与 005 知识库权限的叠加口径未写——AgentOS 整合方案曾登记"知识库挂载继承源数据权限不存在"缺口）
- [ ] CHK005 OQ-1~OQ-4 是否全部消解回填（四概念 ADR、失效引用策略、Key 资源范围、路由规则形态）

## 清晰度（Clarity）

- [ ] CHK006 "档案注入"的**时序与失败语义**是否明确（创建时物化——引用校验失败是拒绝创建还是降级（OQ-2 未定值）；注入发生在门禁解析之前还是之后影响交集判定顺序）
- [ ] CHK007 B2 路由规则的**求值序与冲突裁决**是否定义（FR-007 说规则路由 + 默认兜底；多规则同时命中取谁、规则优先级字段、规则与默认员工同时缺失的行为未写）
- [ ] CHK008 员工级 Key 的**认证主体与审计归属**是否定义（FR-009 限员工资源；Key 发起的会话算谁的成本（Key 持有者 vs 员工）、审计 actor 如何记录未写）
- [ ] CHK009 "我的 ∪ 我参与的"中**成员变更的生效时机**是否明确（认领审批通过后成员列表更新——在途会话的可见性是否追溯，049 口径直接沿用但员工场景需确认）

## 一致性（Consistency）

- [ ] CHK010 **双服务读写口径**是否有守护机制（plan 声明参照 049 对拍先例；employees 集合 chat-api/admin-api 两侧读写的字段契约、状态机枚举一致性测试未列入 FR）
- [ ] CHK011 资产中心类型扩展是否与 045 实际结构一致（registry 现有类型枚举位置、`GET /api/v1/capabilities/list` 的 employee 条目形态需代码核实后定契约，不得假设）
- [ ] CHK012 成本归因声明是否与 035/048 现状一致（FR-006 说经 agent_id 链路；035 的 agent_id 埋点现状与 employee_id 的映射方式（直接复用 vs 新字段）需核实，048 刚删除无写方维度——不得再造悬空维度）
- [ ] CHK013 门户认领复用是否与 037 实际链路一致（FR-004 复用申领审批；037 申领对象现为应用/资产，employee 类型的审批权限码与开通动作需核对现有实现）

## 边界与歧义（Edge Cases & Ambiguity）

- [ ] CHK014 **员工停用与在途会话**的边界是否覆盖（Edge Cases 说在途不中断；停用瞬间正在创建的会话、档案快照已物化但会话未激活的中间态未写）
- [ ] CHK015 **白名单为空**的员工行为是否定义（全拒绝还是继承默认？fail-closed 口径需要显式声明，避免"空白名单=全放行"歧义）
- [ ] CHK016 **员工档案并发修改**与会话创建的竞态是否覆盖（修改白名单瞬间创建会话——快照取修改前还是后、乐观锁口径未写）
- [ ] CHK017 **IM 路由到的员工未对消息发送者开通**时行为是否定义（渠道绑定员工 A，但发送者未认领 A——拒绝、回落默认还是提示认领？FR-007 未覆盖此权限交叉）
