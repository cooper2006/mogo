# Feature Specification: 广场模板分发（员工 / SOP 模板，复制改副本不动原件）

**Feature Branch**: `053-plaza-template-distribution`

**Created**: 2026-11-09

**Status**: Draft

**Input**: 整合方案 §4.4：资产中心 `asset_type` 扩展 `employee` / `sop` 两类模板；上架 → 广场展示 → 用户"复制到自己名下"（clone 语义：副本可改、原件不动）→ 副本走既有申领审批。SOP 模板发布前过 032 评估门禁；模板版本升级不强制覆盖副本。

> **设计来源**：本规约来自 `docs/MOGO-StaffDeck整合方案.md` §4.4（2026-11-09 代码级勘察结论）。StaffDeck 为 AGPL-3.0，**仅借鉴产品设计，不拷贝代码**。
>
> **性质说明**：**已实现（2026-11-09，tasks 29/29）**——模板类型扩展 + 管理端点 + 广场查询 + 克隆（深拷贝/凭证剥离/原件只读）+ SOP 副本落 `dag_definitions`（审批人重解析）+ 员工副本落 `employees` + 版本升级留快照 + US3 P2（副本申领 `require_asset_use` fail-closed / 调试标记 / 克隆数进 016）；双端 vue-tsc 0 错误；OQ-1~OQ-4 已按 spec 已定默认值消解并回填。
>
> **背景事实（代码级核实，2026-11-09）**：045 资产中心统一坐标 `(asset_type, asset_key)` + 四徽标（评级/上架/申领/在用），`GET /api/v1/capabilities/list`（`services/admin-api/app/services/capability_assets/registry.py`，现类型不含 employee/sop）；016 市场强化（质量分/灰度/回滚/低质标记）；001 上架与申领审批；002 版本化；032 评估门禁（publish 卡点已落地）；033 灰度发布；037 门户目录与申领；010 编排定义持久化 `dag_definitions`（`orchestration/store.py`）；051（本批次）提供 employee 实体。

## 定位（一句话）

把 mogo 资产市场从"Skill/能力资产"扩展为**模板广场**：员工与 SOP（编排定义）可作为模板上架分发，用户复制到自己名下得到可编辑副本（原件不可动），副本使用走既有申领审批；**不另建分发体系**——全部复用 045 坐标、016 市场、001 审批、032 门禁。

## 已定决策（2026-11-09，spec 撰写时拍板）

| # | 决策点 | 结论 | 落点 |
| --- | --- | --- | --- |
| 1 | 模板类型 | `asset_type` 扩展 `employee_template` / `sop_template` 两类（与 051 的 `employee` 运行实体区分：**模板是定义，员工/编排是实例**） | capability_assets |

| 3 | 版本升级 | 模板发新版本不强制覆盖副本；副本侧提示"源模板有新版本"，用户手动选择升级（升级 = 三方合并口径过复杂，首期**整份替换并保留旧副本快照**，002 版本化兜底） | 版本提示 |

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 模板上架与广场展示 (Priority: P1) 🎯 MVP

管理员把一个编排定义（SOP）或员工档案发布为模板：过门禁与审批后上架，广场目录可见（分类/搜索/详情/版本），四徽标接入资产中心。

**Why this priority**: 上架是分发链路的起点；复用 045/016/001 既有机制，边际成本最低。

**Independent Test**: 发布 SOP 模板（评估通过）→ 审批通过 → 广场可见、`capabilities/list` 含 `sop_template` 条目；评估不通过 → 发布被拒（032 口径）。

**Acceptance Scenarios**:

1. **Given** 编排定义与评估测试集，**When** 申请上架且评估通过、审批通过，**Then** 模板上架、广场可见、审计记录。
2. **Given** 评估低于阈值，**When** 申请上架，**Then** 发布被拒（032 fail-closed）。
3. **Given** 员工模板档案引用了已下线 Skill，**When** 申请上架，**Then** 校验失败拒绝（决策 #4）。

---

### User Story 2 - 复制到名下并编辑副本 (Priority: P1)

用户在广场选择模板"复制到我的"：得到自己名下的副本（员工或编排定义），可任意编辑；原件不受影响；副本记录源模板坐标与版本。

**Why this priority**: "复制改副本、动不了原件"是 StaffDeck 广场分发的核心语义，也是模板与实例的边界证明。

**Independent Test**: 克隆 SOP 模板 → 断言克隆者名下新定义生成、`template_ref` 正确；编辑副本 → 断言原件内容哈希不变；原件作者修改原件 → 断言副本不受影响。

**Acceptance Scenarios**:

1. **Given** 已上架模板，**When** 用户克隆，**Then** 副本生成于克隆者名下（租户内）、`template_ref` 记录模板坐标 + 版本。
2. **Given** 副本已生成，**When** 克隆者编辑副本，**Then** 原件不变（内容哈希断言）；副本编辑权限归克隆者。
3. **Given** 非上架者/非管理员，**When** 尝试修改原件，**Then** 拒绝（原件只读语义）。
4. **Given** 模板下架，**When** 已克隆副本使用，**Then** 副本不受影响（独立存活）。

---

### User Story 3 - 副本申领使用与版本提示 (Priority: P2)

副本作为员工/编排使用时走既有申领审批（037/001）；源模板有新版本时副本侧出现提示，用户可手动升级（整份替换 + 旧副本快照保留）。

**Why this priority**: 完成"模板 → 副本 → 使用"闭环与版本生命周期；依赖 US1/US2。

**Independent Test**: 副本申领 → 审批通过后可用；模板发 v2 → 副本侧提示；用户升级 → 副本内容 = v2、旧副本快照可查（002）。

**Acceptance Scenarios**:

1. **Given** 副本未开通，**When** 尝试使用，**Then** 拒绝（申领审批 fail-closed，037 口径）。
2. **Given** 源模板发布新版本，**When** 副本 owner 查看，**Then** 见版本提示；不升级则副本行为不变（不强制覆盖）。
3. **Given** 用户选择升级，**When** 执行，**Then** 副本整份替换为新版本内容、旧副本留快照、`template_ref` 更新、审计记录。

---

### Edge Cases

- **克隆时模板恰被下架**：克隆校验上架状态，已下架拒绝（fail-closed）。
- **模板含敏感配置**（凭证引用）：模板 MUST NOT 含凭证明文（034 口径）；克隆不复制凭证，副本需自行配置。
- **副本再分发**：副本默认不可再上架为模板（防止血缘失控）；如需分享走显式"发布为模板"重新过门禁（clarify 定首期是否开放）。
- **同名克隆**：副本名称冲突自动后缀，不覆盖既有资产。
- **员工模板克隆**：副本员工的能力白名单引用按克隆者租户解析，跨租户引用失效则校验报错。
- **评估测试集缺失**：SOP 模板无测试集不得上架（032 口径，不豁免）。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 资产中心 MUST 扩展 `employee_template` / `sop_template` 两类资产坐标，四徽标语义沿用；广场目录支持分类/搜索/详情/版本查看。
- **FR-002**: 模板上架 MUST 过门禁：SOP 过 032 评估（无测试集不得上架）；员工模板校验档案引用有效性；上架走 001 审批，全审计。
- **FR-003**: 克隆 MUST 深拷贝定义到克隆者名下新实体并记录 `template_ref`（坐标 + 版本）；副本可编辑、原件对非上架者只读；原件变更不影响副本。
- **FR-004**: 模板 MUST NOT 含凭证明文；克隆不复制凭证（034 口径）。
- **FR-005**: 模板新版本 MUST NOT 强制覆盖副本；副本侧提示 + 手动升级（整份替换 + 旧副本快照，002 版本化）；升级全审计。
- **FR-006**: 模板下架/删除 MUST 不影响已克隆副本；克隆时模板已下架 MUST 拒绝。
- **FR-007**: 副本使用 MUST 走既有申领审批（037/001），未开通 fail-closed。
- **FR-008**: 模板可见性 MUST 租户内（跨租户 fail-closed）；广场查询经既有鉴权。
- **FR-009**: （决策 #7）SOP 模板调试 MUST 以显式调试标记试跑，副作用边界按 clarify 口径；调试记录可查。
- **FR-010**: 前端 MUST 中英双语（宪法 IV）：广场页（user-web 门户侧）+ 模板管理（admin-web）。
- **FR-011**: 模板质量信号 MUST 接入 016 既有机制（克隆数/使用效果可统计，低质标记口径沿用），不新建评分体系。

### Key Entities

- **AssetTemplate**: 模板（类型 employee_template/sop_template、定义内容引用、版本序列、上架状态、门禁报告引用、上架者）。
- **TemplateClone**: 克隆记录（副本实体坐标、克隆者、template_ref、克隆时刻）。
- **TemplateVersion**: 模板版本（版本号/内容快照/发布时刻/门禁报告），002 版本化口径。
- **UpgradeRecord**: 副本升级记录（旧快照引用/新版本/操作者/时刻）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 上架 → 广场展示 → 克隆 → 编辑副本 → 申领使用全链路 E2E；原件不变性有哈希断言。
- **SC-002**: 门禁有效：评估不达标/引用失效/无测试集三类上架均被拒。
- **SC-003**: 版本生命周期：新版本不强制覆盖、手动升级留快照、下架不伤副本，各有契约测试。
- **SC-004**: 凭证零泄漏：模板内容与克隆产物无凭证明文（扫描断言）。
- **SC-005**: 首批 2–3 个种子模板可演示（数量不承诺，SC 以"至少 1 个员工模板 + 1 个 SOP 模板跑通全链路"为底线）。

## Assumptions

- 模板定义载体复用既有实体：SOP = dag_definitions 编排定义；员工 = 051 employees 档案（051 B1 未落地时员工模板类型可先建坐标、克隆挂起，clarify 定顺序）。
- 广场不另建前端应用：user-web 门户侧新增广场页（ADR-7 Web 口径）。
- 克隆数统计经 016 既有监控面，不新建埋点体系。
- 种子模板内容自行编写，不拷贝 StaffDeck（AGPL-3.0）素材。

## 待澄清（clarify 门禁）

- **OQ-1**: 调试工作区的副作用边界（调试会话的工具调用是全沙箱、只读标记还是白名单子集）。
- **OQ-2**: 副本"发布为模板"再分发首期是否开放（默认禁止）。
- **OQ-3**: 员工模板与 051 的落地顺序（051 B1 先行则员工模板克隆可用；否则首期仅 SOP 模板）。
- **OQ-4**: 升级"整份替换"对副本已编辑内容的冲突提示口径（覆盖前二次确认 + 旧快照，是否需要 diff 展示）。

## 跨特性关系（被依赖方视角，双向声明）

- **与 045（asset-center）**：资产坐标扩展，统一列表与四徽标不变。
- **与 016（skill-market-hardening）**：质量信号/低质标记沿用，不新建评分。
- **与 001/037**：上架审批与副本申领复用既有链路。
- **与 032/033**：SOP 上架门禁复用评估卡点；灰度可选（模板上架是否走 033 灰度 clarify 不强制）。
- **与 002**：模板版本与副本快照走版本化口径。
- **与 034**：凭证零明文约束。
- **与 051（本批次）**：员工模板克隆依赖 051 B1 员工实体（OQ-3 定顺序）；**SOP 模板不依赖 051，可先行**。
- **与 050（本批次）**：含转人工节点的 SOP 模板克隆后审批人按克隆者租户重新解析（原审批人引用不跨租户携带）。

## Non-Goals

- 不承诺模板数量（首批 2–3 个演示，运营目标不写对外承诺）。
- 不做三方合并式升级（整份替换 + 快照，YAGNI）。
- 不做跨租户模板市场（租户内广场）。
- 不做模板付费/计量分发（community 版无计费口径）。
- 不拷贝 StaffDeck（AGPL-3.0）代码与素材。
