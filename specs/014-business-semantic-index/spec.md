# Feature Specification: Business System Semantic Index

**Feature Branch**: `014-business-semantic-index`

**Created**: 2026-07-08

**Status**: Draft

**Input**: 补齐规划文档清单 10（P2 规模化生态）"业务系统语义索引"（知识库《PilotMind》业务索引）：在 RAG 之上对接 CRM/采购/财务等业务系统做语义检索，让 Agent 能"按业务语义"（而非仅文档文本）召回业务实体与状态。

## User Scenarios & Testing *(mandatory)*

用户故事按优先级排列，每个独立可交付、可测试。

### User Story 1 (P1) — 业务系统语义索引构建

对接一个业务系统（CRM/采购/财务之一，首期 1 个），将其业务实体（客户/订单/供应商/账目等）语义索引化，进入检索范围。

**Acceptance Scenarios:**
- 对接 CRM → 客户/订单实体被语义索引
- 索引随业务数据更新（增量）
- 未对接的业务系统 → 不进入检索

### User Story 2 (P1) — 按业务语义检索

用户/Agent 用自然语言业务问题检索，命中业务实体而非仅文档文本；结果带业务实体定位。

**Acceptance Scenarios:**
- 问"上季度华东区成交额" → 召回财务/CRM 业务数据
- 问"供应商 X 的未交付订单" → 召回采购/CRM 实体
- 命中 → 附带业务实体来源（表/字段/记录定位）
- 无命中 → 明确"未检索到相关业务数据"

### User Story 3 (P2) — 多业务系统统一索引

多个业务系统（CRM+采购+财务）统一语义索引，跨系统联查（如"客户 X 的订单与回款"）。

**Acceptance Scenarios:**
- 多系统统一索引 → 跨系统实体可关联
- 跨系统联查 → 结果可溯源到各系统
- 系统间实体关联（客户/订单/账目）可对齐

### Notes / Assumptions
- 本特性补齐规划文档清单 10（P2 规模化生态，后置），属缺口新特性
- 现状：MOVO 有 RAG（文档检索，特性 005），业务语义索引是在 RAG 之上对接业务系统的语义层
- 与特性 005（knowledge-rag）的关系：业务索引复用 005 的检索客户端与引用锚点机制
- 与特性 004（SkillHub/工具）的关系：业务系统可经 MCP/工具接入，语义索引是"检索侧"的增强
- 与特性 015（知识图谱层）的关系：业务实体关联可演进为知识图谱（15 是其结构化扩展）
- 业务系统连接凭据（DB 账号/API key）不进仓库（001 安全原则）

## Functional Requirements

- FR-1: 对接至少 1 个业务系统（CRM/采购/财务），实体语义索引化；**首期 = CRM（DB 直连只读副本），采购/财务按节奏补齐；实体类型 = 客户/订单/供应商/账目（4 类，`biz_entities.entity_types` 可配置）**
- FR-2: 索引支持增量更新（业务数据变化）；**增量机制 = 定时拉取（复用 `scheduled_tasks` daily/weekly），不做 CDC；全量首刷在首次接入时人工触发一次**
- FR-3: 按业务语义检索命中业务实体，结果带实体来源定位；**来源定位深度 = 业务系统名 + 实体类型 + 记录 ID（三级）**
- FR-4: 未命中明确标注，不编造业务数据
- FR-5: 支持多业务系统统一索引与跨系统联查；**联查关联键 = 各系统业务主键（客户编号/订单号/供应商编码/账期），跨系统对齐靠业务主键映射**
- FR-6: 业务实体间关联（客户/订单/账目）可对齐；**对齐失败（不同系统主键不一致）标记"未对齐"，不拒绝联查（未对齐实体仅返本系统结果）**
- FR-7: 检索复用 005 检索客户端与引用锚点
- FR-8: 业务系统连接凭据不入仓库，可配置
- FR-9: 业务索引访问受 001 治理层权限约束；**业务数据权限码 `bizdata:read`（001 权限码 resource 含业务系统维度）**
- FR-10: **业务 PII 字段（手机号/身份证等）走 001 脱敏（mask/hash），索引前脱敏，检索结果不回填明文（与 001 PII 策略联动）**
- FR-11: **业务系统连接不可用（DB 副本宕机）时，检索明确标注"数据源不可用"（不返回陈旧索引冒充实时）**
- FR-12: **接受只读副本延迟，检索结果标注数据同步时间戳（供用户判断新鲜度）**

## Non-Goals
- 不替代业务系统（MOVO 做检索增强，不写入业务库）
- 不实现业务数据双向同步（仅读索引）
- 不实现知识图谱推理（属 015，本特性是检索层）
- 不改变 RAG 既有文档检索契约（业务索引是叠加层）

## Success Criteria
- 首期业务系统实体 100% 入索引
- 业务语义检索命中带实体来源
- 跨系统联查结果可溯源
- 业务索引 100% 受权限约束

### 跨特性关系（被依赖方视角，2026-07-08 双向声明）
- **与 015（knowledge-graph-layer）**：014 的 `biz_entities` **可被 015 的图谱节点指针引用**（`kg_nodes.source_ref` 指向业务实体 ID，不做数据复制）——014 的业务实体是图谱的实体来源之一。
- **与 005（knowledge-rag）**：014 的检索复用 005 的检索客户端与引用锚点（005 的 RetrievalChunkItem 扩展业务实体项类型）。
- **与 001（gatekeeper）**：014 的业务数据权限码 `bizdata:read` 注册于 001 权限码模型（resource 含业务系统维度）。
