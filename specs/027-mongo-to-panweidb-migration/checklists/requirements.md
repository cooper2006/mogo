- [x] CHK017 与 020 platform-multi-tenancy 的关系：租户隔离在表结构中以 `tenant_id` 列承载，租户销毁流程的批量删除能力被显式保全（FR-029），不因后端更换而失效？
- [x] CHK018 与 026 performance-scalability 的关系：026 的「数据库性能」（索引覆盖率、连接池配置）在本特性中体现为 `tenant_id` 索引 + JSON 表达式索引 + GIN，以及连接池最小/最大/超时配置（FR-005）；**026 的优化项不因换库而丢失**，但 026 的 `slow_query_log` 等 MongoDB 专有手段在新后端需另行等价（已在 plan.md 登记）？
- [x] CHK019 与 023 observability-resilience 的关系：健康检查输出的后端快照（`backend`/`target`/`reachable`）为可观测性提供接入点（FR-006 + T011）？
- [x] CHK020 与 002 session-versioning / 017 three-scope-memory 等**使用聚合管道或 `$lookup`** 的特性关系：这些调用点在 R1 下显式失败，已在 tasks.md Phase 9 列为 R2 改写项（T052），不会静默产生错误结果？
