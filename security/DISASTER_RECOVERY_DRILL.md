# 灾备演练规程（QF-710）

> 本文档定义了 MOGO 平台的灾备演练（DR Drill）流程、检查清单和记录模板。
> 演练结果必须可审计、可追溯，保留至少 1 年。

## 演练类型

| 类型 | 频率 | 范围 | 判定标准 |
|------|------|------|----------|
| **桌面演练（Tabletop）** | 每季度 | 全流程桌面推演 | 参与方能完整描述恢复步骤 |
| **组件演练（Component）** | 每半年 | 单组件恢复（DB / 存储 / 配置） | 该组件恢复时间 ≤ RTO |
| **全量演练（Full DR）** | 每年 | 全系统从备份恢复 | 全系统恢复时间 ≤ RTO，数据丢失 ≤ RPO |

## 演练前置条件

- [ ] 最近一次全量备份在 24 小时内（`backup_metadata` 集合验证）
- [ ] 备份校验和验证通过（`sha256sum` 与记录一致）
- [ ] 恢复环境准备就绪（测试集群 / 隔离网络）
- [ ] 演练通知已发出（至少提前 2 个工作日）
- [ ] 值班人员到位（运维 + DBA + 开发负责人）

## 演练步骤

### 1. 故障注入

记录演练开始时间和故障场景。

```
演练编号：DR-YYYY-NNN
故障场景：[单节点故障 / 磁盘故障 / 集群故障 / 数据损坏]
开始时间：YYYY-MM-DD HH:MM:SS UTC+8
值班人员：[姓名列表]
```

### 2. 故障检测

- [ ] 监控系统告警（PagerDuty / 飞书机器人）
- [ ] 告警响应时间 ≤ 5 分钟
- [ ] 故障确认（值班人员确认非误报）

**实测响应时间**：______ 分钟

### 3. 启动恢复流程

- [ ] 通知相关方（技术负责人 / 客服 / 法务）
- [ ] 切换到灾备环境（DNS / 负载均衡）
- [ ] 从最近备份恢复数据

**备份信息**：
- 备份时间：______
- 备份位置：______
- 数据密钥：______（Vault/KMS 路径）

### 4. 数据恢复

按 `docs/backup-recovery.md` 中的恢复步骤执行。

**恢复耗时**：
| 步骤 | 计划时间 | 实测时间 | 是否达标 |
|------|----------|----------|----------|
| 解密备份文件 | 5 min | ______ | ☐ |
| 恢复 MongoDB 主数据 | 15 min | ______ | ☐ |
| 恢复应用数据 | 10 min | ______ | ☐ |
| 恢复文件存储 | 10 min | ______ | ☐ |
| 恢复配置 | 5 min | ______ | ☐ |
| **合计** | **45 min** | ______ | ☐ |

### 5. 数据完整性验证

- [ ] 数据行数对比（源 vs 恢复后）
- [ ] 关键记录抽样验证（10 条核心业务记录）
- [ ] 审计日志链完整性验证（`audit_events` 哈希链）
- [ ] 用户登录测试（3 个不同角色）
- [ ] API 功能验证（核心 5 个端点）

**数据丢失量**：______（应 ≤ RPO = 15 分钟）

### 6. 服务验证

- [ ] 健康检查通过（`/api/healthz`）
- [ ] 认证流程正常（登录 + MFA）
- [ ] 核心业务功能正常
- [ ] 外部服务连接正常

**恢复时间目标（RTO）**：
- 计划 RTO：30 分钟
- 实测 RTO：______ 分钟
- 是否达标：☐ 是 ☐ 否

### 7. 演练结束

```
结束时间：YYYY-MM-DD HH:MM:SS UTC+8
总耗时：______ 分钟
RTO 达标：☐ 是 ☐ 否
RPO 达标：☐ 是 ☐ 否
```
