# ADR-8：统一「项目」概念——项目 = 工作目录（workspace）

- **状态**：Accepted（2026-10-30 决策；含当日 17:43 修订"以 user-web 的项目概念为准"、17:55 修订"五个待确认项拍板"）

## 1. 一句话背景

仓库里有三个同名的「项目」：user-web 的项目（本地目录 + `desktop_projects`）、chat-api 的项目（同一条 `desktop_projects` 记录）、042 的配额项目（`quota_projects`，只有成员没有目录与会话）。而 **user-web 是自研客户端**，它里面的项目交互就是产品事实，不是某个上游客户端的实现细节——所以以它为准收敛成一个概念。

## 2. 决策

| # | 问题 | 决策 |
|---|---|---|
| D0 | 以谁的概念为准 | **以 user-web 的项目概念为准**：项目 = 工作目录（`workspace_id`）。chat-api 与配额项目都向它对齐，不引入第二套抽象 |
| D1 | 纯个人项目是否允许 | **允许**。项目天然属于创建者（`tenant_id + user_id`），不要求成员、不要求共享 |
| D2 | web 会话（无本地目录）怎么归集 | **默认项目**，`project_id` **固定为字符串 `"default"`**；每租户每用户一条，"未分组"就是默认项目，会话 `project_id` 不留空。所有查询本就带 `tenant_id`，`"default"` 只是租户内保留键，跨租户同名不构成问题 |
| D3 | 目录绑定是否强制 | **可选**。项目本来就是目录，但默认项目没有目录；有目录的项目才能跑 code |
| D4 | 回填范围 | **全量**（遍历 `agent_kernel_bindings`，一次性脚本，可重入、带失败清单） |
| D5 | 配额是否按项目加约束 | **不加**。用量事实主体是**会话**，用户/项目只是会话的属性；配额默认不限额，不作为关键项 |
| D6 | `desktop_projects` 是否改名 | **改名为 `projects`**。集合名 + chat-api 路由 + user-web 客户端同步改，一次性 `renameCollection`，HTTP 契约不变 |
| D7 | 目录消失后怎么处理 | **自动归档**（`status = archived`），不引入 `missing-dir` 中间态。由客户端对账上报（只有客户端知道目录在不在），服务端不做定时扫描 |
| D8 | 团队/项目配置入口 | **独立菜单「项目管理」**，只含项目。**没有"团队"概念**：部门维度归组织管理，`scope_type='team'` 存储值不改、对外文案统一称"部门" |

## 3. 由本决策连带确定的结论

- **035 的「空间」维度改名「项目」**，`TokenUsageRecord.workspace_id` → `project_id`（该字段线上恒空、无消费方，改名零成本）。
- **业务线维度取消**，成本归集段由 6 段降为 5 段（**租户** / 用户 / 部门 / Agent / 项目）。理由与删除清单见正本文档 §4.1–4.3。
- **「企业」维度改名「租户」**（同批决策，维度保留）：该段本就读 `tenant_id`，`enterpriseAttribution` → `tenantAttribution`；它是 `reconciles` 的对账锚点（租户隔离下恒为单桶 = 总量），不是可分组维度。见正本文档 §4.4。
- **042 的 `quota_projects` 成员语义废弃**：项目没有成员。项目层策略的 `scope_id` 直接取 `project_id`，用量改为 `group by project_id`（一次调用只属一个项目，不会重复计数）。
- **admin-web 不再提供「新建项目」**：项目由员工在自己机器上选目录产生，管理员无法替别人选目录。治理面只做只读列表、配额、成本视图与告警。
- **归档不等于删除**：归档项目保留策略、历史成本与会话，只是不再参与配额取小；策略行不删，避免恢复后配置丢失。

## 4. 明确放弃的方案

上一版 ADR 曾设计「逻辑项目（租户级实体）+ `project_workspaces`（每用户每设备绑定表）」的两层模型。**放弃**：

- 它假设"一个项目可以多个人、各自绑定不同本地路径"，但 user-web 的项目是用户自己选的一个目录，没有"多人共享同一项目"的产品形态，为它预建绑定表属于过度设计。
- 两层模型会让"项目"出现两个 id，而 user-web 侧边栏、会话绑定、`desktop_projects` 全都已经用 `workspace_id` 作为键，引入第二个 id 要改全链路。

**保留升级路径**：将来真要做"团队共享项目"，再加 `project_workspaces`（项目 × 用户 × 设备）、把 `workspace_id` 降级为它的属性即可，现有主键不用推翻。
